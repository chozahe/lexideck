# Проверка перевода выделенного текста в Brave — #9

Проверено в Brave Browser 154.1.96.61 на Linux, в отдельном чистом профиле,
с настоящим расширением Manifest V3 и настоящим `chrome.sidePanel.open()`.
API управляемый: `tests/server.js`. Вызов открытия панели не подменяется.

## Воспроизведение исходной ошибки

До исправления: выделить `She took off her coat and wore her coat.` на
HTTP-странице и отправить настоящий `Ctrl+Shift+Y` через `wtype`.
Панель не создавалась; вызов `sidePanel.open()` возвращал:

```
`sidePanel.open()` may only be called in response to a user gesture.
```

Временное сохранение ошибки в тестовом профиле удалено после диагностики.
Причина: переход через `await chrome.tabs.sendMessage()` теряет user gesture.
Callback этого API сохраняет жест, поэтому открытие выполняется в callback,
до ожидания записи выделения в хранилище.

## Результат после исправления

Команды для повторения проверки:

```bash
node tests/server.js
node scripts/check-brave-selection.js
```

При занятом стандартном порту можно запустить сервер с `PORT=4189` и проверку
с `BRAVE_TEST_ORIGIN=http://127.0.0.1:4189`.

Проверяющий скрипт подтвердил, что до хоткея `panel.html` отсутствует среди
DevTools targets. После хоткея настоящая панель появилась. Через DevTools
прочитаны её исходный текст и видимый перевод:
`Она сняла пальто и надела пальто.`. Поле ошибки пустое.
Вывод: `PASS: закрытая панель → выделение → Ctrl+Shift+Y → открытая панель и автоматический перевод.`

## Дополнительные проверки и границы

Playwright проверяет автоматический перевод, видимое ожидание, исправление,
ошибку API, замену запроса и защиту от запоздалого ответа, порядок значений,
сохранение основной формы и устойчивого выражения с контекстом употребления.
Существующая проверка маршрутизации контекстного меню сохранена.

Проверка Brave требует графической сессии Wayland и `wtype`; она посылает
настоящий хоткей в активное окно отдельного тестового браузера. API возвращает
управляемые ответы, поэтому качество внешней модели не оценивается.
Контекстное меню проверено существующей маршрутизацией, а не вручную в Brave.
Область захвата и её user gesture относятся к #10 и этой проверкой не покрыты.
