# Проверка задач #20 и #21

Дата проверки: 16 октября 2026 года. Среда: Playwright 1.63, Chromium headless (`HeadlessChrome/153.0.8010.12`), Linux, CSS viewport задавался через `page.setViewportSize`; реальный браузерный интерфейс и системный масштаб ОС не использовались.

## Контраст и темы (#20)

`tests/visual-contrast.spec.js` проверяет основные активные действия на экранах перевода, повторения, словаря и настроек в Latte и Macchiato. Для каждой кнопки измерены normal, hover, focus и active; вычисленный контраст текста с фоном проходит порог 4,5:1. Отдельно проверяются success, error, pending и нейтральный статус. Тесты темы подтверждают Latte, Macchiato и system, синхронизацию открытых страниц, видимый фокус, а также оформление ошибки сохранения темы. Ошибки настроек проверяются существующими сценариями `tests/settings.spec.js`; их сообщение сохраняет состояние error.

Disabled-состояния не включены в порог для активного текста. У кнопок с `:disabled` используется приглушённый стиль `opacity: .62`; отдельное численное измерение их контраста не проводилось, порог 4,5:1 к ним не применялся.

## Переполнение и масштабирование (#21)

`tests/visual-overflow.spec.js` задаёт основную форму ровно в 180 символов без пробелов (`"слово"` × 36), а также длинные значения, контексты, примеры и сообщение ошибки. Четыре экрана (перевод, повторение, словарь, настройки) проверены в Latte, Macchiato и системных светлом/тёмном режимах при CSS viewport 320, 390, 640 и 1280 px. Это 64 сочетания экрана, ширины и темы. Во всех сочетаниях `documentElement.scrollWidth` и `body.scrollWidth` совпали с шириной viewport; тест не обнаружил горизонтального переполнения. Элементы длинного содержимого переносились, их текст оставался в DOM и читался целиком.

Для проверки увеличения 200% и 400% на desktop viewport 1280 CSS px использованы соответственно эффективные layout viewport 640 и 320 CSS px. В этих размерах все четыре экрана и действия оставались доступны. Это проверка адаптивного layout при эквивалентной ширине, а не изменение browser zoom через интерфейс Chromium; отдельная ручная проверка native zoom не выполнялась.

Снимки в `/tmp/lexideck-visual-{panel,review,settings,vocabulary}-{latte,macchiato}.png` визуально просмотрены: длинная форма, значения, контексты, примеры и ошибка переносятся в пределах панели, основные действия видны. В длинных карточках содержимое занимает много вертикального места, но не обрезается.
