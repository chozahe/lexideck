# Документация предметной области

## Перед изучением проекта

Прочитай `CONTEXT.md` в корне и решения из `docs/adr/`,
относящиеся к текущей задаче.

Если появится `CONTEXT-MAP.md`, прочитай его и документы
контекстов, относящихся к задаче, включая их локальные ADR.

Если документов нет, продолжай работу без уведомления
об их отсутствии и без предложения заранее создать их.
Навык `domain-modeling` создаёт их по мере определения
терминов и принятия решений.

## Структура

Используется один контекст:
- `CONTEXT.md` — термины и модель предметной области.
- `docs/adr/` — записи архитектурных решений.

## Терминология

Используй термины из `CONTEXT.md` в задачах, предложениях,
гипотезах и названиях тестов.

Если понятия нет в словаре, проверь уместность термина.
Реальный пробел отметь для работы через `domain-modeling`.

## Противоречия решениям

Если предложение противоречит существующему ADR,
явно укажи номер решения и причину его пересмотра.
